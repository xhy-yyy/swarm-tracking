# 深度相机 + 雷达高度记忆加入避障

## 为什么

二维雷达的扫描面在机体原点下方 0.1125 m，只有薄薄一层。深度相机下倾 25°，画面上沿在水平线以下 1.6°，光心在原点下方 0.20 m，所以看不到比自己高的东西。相机零姿态安装偏移为 `(0.0205, 0, -0.20)` m，通过固定关节连接云台末端。

以加油站顶棚为例（高度均为本地帧，即世界高度减 0.22 m）：

| 部位 | 高度 |
|---|---|
| 檐口底 | 3.047 m |
| 横梁底 | 2.951 m |
| 棚内吊顶 | 3.211 m |

跟踪高度 3.2 时，扫描面在 3.0875，只比檐口底高 4 cm。飞机往下掉 4 cm，雷达就从檐口下方扫过去，而机体最高处（桨盘顶 +0.085 m）仍会和檐口相撞。EGO 地图每帧清空，漏扫一帧棚边就从地图上消失了。

顶棚其实被看到过：巡航和下降时，相机能从上方看到棚顶和檐口；下降时，雷达扫描面会从 4.39 扫到 3.09。问题是这些观测以前都没有保留下来。

## 数据流

```
深度图(整幅) + pose_relay ─┐
lidar_cloud_world_3d ──────┼─> body_band_cloud.py ─> body_band_cloud ─┬─> laser_scan_to_world_cloud 合并 ─> obstacle_cloud_world ─> EGO
body_band_request <─ fly_px4_1                    └─> body_band_overhead ┴─> fly_px4_1 (只算碰撞, 不挡视线)
```

- `body_band_cloud.py`（每架飞机一个）：
  - 深度图整幅按 4×4 取最近深度，雷达点用真实扫描面高度（odom z − 0.1125）。
  - 记忆按 0.2×0.2×0.1 m 体素保存 15 s，同一体素至少命中 2 次才发布。
  - 只发布落在机体高度带内的体素。高度带 = [min(当前, 目标) − 0.52, max(当前, 目标) + 0.39]：机体脚架在 −0.22、桨盘顶在 +0.085，各加 0.3 m 余量；升降途中高度带延伸到目标高度。
  - 地面和行人（头顶 1.88 m）永远不在带内。
  - 友机按里程计剔除，只用新鲜的里程计。
  - 深度画面里能完整"看穿"的残影体素会被清掉。贴着画面边缘、看不全的体素不清，雷达记住的点也不清。
- `body_band_overhead`：其中的"上方结构证据"，包括深度点，以及雷达在偏离当前扫描面超过一个体素的高度扫到的点。`fly_px4_1` 不把站位放在这类墙后面（即棚下）。同一扫描高度上记住的楼墙不算，仍然可以绕楼跟随。
- `fly_px4_1`：
  - 高度带点只参与碰撞判断：离墙距离、能否直飞、PID 速度过滤。
  - 站位到行人的视线判断只看雷达墙面，因为棚子不挡相机往下看。
  - 行人在大顶棚下、5.5 m 一圈都在棚下时，向外各加 2.5 m 再试两圈。
  - 仍然选不到站位时，如果行人在 12 m 内，就在上一个棚外站位继续观察，最多 10 s 后才 reject。

## 什么时候工作

`fly_px4_1` 以 10 Hz 发布 `/<ns>/body_band_request`，内容是 `[目标高度, active]`。

- **只在 TRACK 或跟踪后的归航阶段 active=1**。此时才订阅深度图；视觉在跟踪时本来就订阅同一路深度，所以不新增渲染时段。
- 巡逻时不订阅、不发布，`obstacle_cloud_world` 和 `lidar_cloud_world` 内容一样，巡逻行为不变。
- 开销：单帧深度处理约 3 ms，10 Hz 约占一个核的 3%。

## 开关和参数

- `swarm_relay_ego.launch body_band:=false`：完全回到只用二维雷达，方便 A/B 对比。
- `body_band_cloud.py` 私有参数：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `band_below` / `band_above` | 0.52 / 0.39 | 高度带下沿 / 上沿余量 |
| `memory_sec` | 15 | 记忆保留时长 (s) |
| `radius` | 25 | 记忆和发布半径 (m) |
| `min_hits` | 2 | 发布所需最少命中次数 |
| `depth_rate` | 10 | 深度处理频率 (Hz) |
| `depth_max_range` | 9 | 深度最大使用距离 (m) |
| `enable_depth` | true | 是否使用深度 |
| `enable_lidar_memory` | true | 是否使用雷达高度记忆 |
| `gimbal_tilt_max_deg` | 6 | 云台偏角超过此值时跳过深度帧 |

- `fly_px4_1` 私有参数：`standoff_band_hold_sec`（默认 10）、`standoff_band_hold_dist`（默认 12）。

## 验证

```
cd $SWARM_WS/build/fly_px4 && ctest   # 含 body_band_cloud (投影/记忆/高度带/看穿清除) 与
                                        # track_obstacle_avoidance (只算碰撞的点不挡视线、棚下站位硬排除)
python3 test/smoke_body_band_cloud.py     # 节点级: 巡逻不开深度; 下降记住檐口; 掉高 5cm 仍保留; 合并进 EGO 点云
python3 test/smoke_canopy_band.py         # 真实 fly_px4_1: 原来进棚 18s; 现在不进棚、EGO 目标不在棚下、棚外 10.5m 内观察
python3 test/smoke_track_avoidance.py     # 原有楼区避障回归 (开阔路段 PID 输出不变)
```

以上测试都在独立的 roscore 上运行，用的是假传感器数据，**不能代替 Gazebo 实飞**。

## 仍然防不住的情况

- 飞机一直在跟踪高度上，从远处平飞接近顶棚，中途没有下降或从上方看过：此时相机看不到檐口，只有雷达在额定高度下能擦到檐口底（余量 4 cm）。这次加的雷达高度记忆会把扫到过的部分记 15 s，但从来没扫到过的就没有办法。
- 站位规则偏保守：行人从顶棚另一侧离开时，飞机不会绕棚去追，而是在棚外最多观察 10 s 后放弃，交给其他飞机。
- 巡航高度（4.5 m）不受这次改动影响。
